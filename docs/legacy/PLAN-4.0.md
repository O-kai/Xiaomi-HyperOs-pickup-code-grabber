## 一、现状审计（为什么不能直接发 4.8）

1. **发布基线失真**：`app/build.gradle:13-14` 是 400/4.0.0，`app/AndroidManifest.xml:4-5` 还是 310/3.1.0；现有 release APK 仍是 4.0.0(400)，构建时间早于 v4.8 提交。手机上的 4.0、本地 v4.8、线上 3.1.0 不是同一条发布线。
2. **产品闭环缺失**：所有分支都没有本地取件库、`AppWidget`、小组件；App 仍是“短信 → 小米笔记/ColorOS”的桥，首页不是待取件。
3. **IPC 安全缺口**：`TodoProvider`、`SmsEventReceiver`、`LauncherActivity` exported 且缺少调用方校验；任意 App 可伪造短信、触发写库/通知，或把码标记已取件。
4. **UI 维护债**：`LauncherActivity` 2452 行；4.x UI 改动约 4000 行；信息架构仍以“体检/设置”为中心，不是以“取件”为中心。
5. **测试/发布债**：现有测试以纯逻辑为主，跨进程、Room、Widget、安全入口没有自动化；CI 只在 tag/手动时构建，不跑测试。
6. **底层不是全坏**：内置 sqlite3 `p_align=0x4000`（16KB 对齐），release 证书 `CN=PickupCodeGrabber`，说明底层资产可用，问题主要在应用骨架与发布收口。

## 三、阶段与验收

### Stage 0：基线冻结与安全收口

**产出**

- 工作副本 `pickup-code-grabber-4.0/`（原目录只读保留）。
- 分支 `release/4.0`；内部追溯 tag `internal/3.2.0` … `internal/3.6.0`。
- `version.properties`；Manifest 去版本号；`checkVersion`。
- IPC 安全修复 + 安全单测。
- 重建 3.6.0-internal APK，真机跑通现有功能。
- 构建 spike：Compose/Room/Gradle/AGP/compileSdk 是否可行；失败则回退 Java UI 方案。

**验收**

- 现有短信/通知/写入/通知栏功能不回归。
- shell UID 2000 调用 Provider 被拒绝；`done` extra 不再生效；旧 Receiver 不再暴露。
- 版本号只从 `version.properties` 读取。
- 基线 APK 可安装、可覆盖 3.1.0、可回滚。

### Stage 1：核心分层与行为锁定

**产出**

- `:core`、`:contract` 模块；提取/规则/模型迁入。
- `rules.json` 单源 + Gradle 生成 `RulesDefaults.java` + asset。
- 特征化测试（≥100 条语料）与现有 28/13/21/45 测试迁移。
- `:hook` 依赖树检查（禁止 AndroidX）。

**验收**

- 重构前后提取结果 100% 一致（码/来源/地点/层级/规则 ID）。
- `:core` 可在普通 JVM 跑全量测试。
- `:hook` 不含 Compose/Room/AndroidX。
- 真机短信/通知链路与基线一致。

### Stage 2：本地优先 + 小组件

**产出**

- Room schema、Repository、Outbox、`PickupSink` 接口。
- `TodoProvider` → 本地库 → 通知 → 小组件闭环。
- 现有 UI 增加一个最小“待取件”列表用于验证。
- 写穿小米笔记/ColorOS；失败重试与可见状态。
- 数据保留期、清空、导出（导出可放 P1）。

**验收**

- 短信→本地→通知→小组件→已取件→系统待办全链路通过。
- 重复事件只建一条；App 被杀/重启/手机重启不丢。
- 系统待办失败不影响本地记录，界面有“同步失败”与重试。
- 小组件 1 秒内更新，PendingIntent 不串。

### Stage 3：UI 5.0 与双模式

**产出**

- Compose App 壳；简洁/进阶两套导航。
- 首启选择页 + 配置引导。
- 首页待取件、详情、手动添加、通知/小组件入口。
- 深色/浅色、边到边、字体缩放、无障碍。
- 设置：模式切换、写入目标、外观、更新、隐私、关于。

**验收**

- 首启 2 分钟内完成选择 + 配置（有 root 前提）。
- 简洁模式打开→复制 ≤ 2 次点击。
- 进阶模式功能不少于 3.1.0 + 4.8 并集。
- 切模式数据不变；深色/1.3×/手势导航无遮挡。
- 用户真机验收通过。

### Stage 4：后端、规则与诊断收口

**产出**

- 小米笔记 / ColorOS 日历 / ColorOS 便签三个 `PickupSink`。
- 后端健康检查、schema 变化提示、切换“仅本地”。
- 规则解释性结果（tier/ruleId/reasons）；链路测试展示“为什么”。
- 诊断 JSON、Hook 能力矩阵、脱敏预览。
- 错题本默认关闭/30 天过期/一键清空。

**验收**

- 三种后端在可用设备上写入/标记通过；不可用设备明确提示。
- 规则单源一致；空/坏规则拒绝加载并回退。
- 诊断报告不含完整手机号/地址/短信正文。
- 安全测试全过。

### Stage 5：毕业测试与发布

**产出**

- 全量测试报告、真机验收记录、48h soak 记录。
- 4.0.0 签名 APK、SHA-256、CHANGELOG、README、截图。
- GitHub Release / LSPosed 镜像 / 酷安文案（经确认后发布）。
- 回滚包与回滚说明。

**验收**

- 发布门槛全过（见 `TEST-RELEASE-4.0.md`）。
- 用户明确确认推送。
- 发布后 7 天反馈窗口与 4.0.1 修复预案。

## 四、依赖关系

```
Stage 0 安全/版本/构建 spike
   ↓
Stage 1 核心分层/规则单源/特征化测试
   ↓
Stage 2 本地库/Outbox/小组件
   ↓
Stage 3 Compose 双模式/首页
   ↓
Stage 4 后端/诊断/规则解释
   ↓
Stage 5 毕业测试/发布
```

- UI 必须等数据模型稳定后再做，避免“先画壳再改数据”。
- 小组件可以和 UI 并行，但必须先有 Room。
- 后端写穿可以和 Stage 2 并行，但默认不阻塞本地闭环。
- 安全修复必须在任何对外构建之前。

## 五、工作方式

- **每个 Stage 一次对接**：先给用户看阶段产出/截图/测试结果，再进入下一阶段。
- **本地 commit 可留痕**；push/Release/镜像必须用户确认。
- **临时文件只放项目目录**（`docs/`、`test/out/`、`tools/`），不散落到 `D:\project` 根目录。
- **文档随代码更新**：架构/版本/测试/UI 任一变更，同步更新对应文档。
- **不静默改范围**：P0 变更需更新本文档；新想法进 P1/P2 或 4.0.1。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Compose/Room 升级导致构建不稳 | 阻塞 UI | Stage 0 spike；失败保持 Java UI，先交付本地库/小组件 |
| targetSdk 34→35/36 触发 Android 17 行为变更 | 兼容性 | 4.0 先保持 34；单独兼容性任务，不阻塞核心 |
| 小米笔记/ColorOS schema 变化 | 写穿失败 | 本地库兜底 + 健康检查 + “仅本地”开关 |
| ColorOS 无真机 | 回归不足 | 标记社区验证；不阻塞小米主线；保留接口 |
| 小组件 OEM 刷新限制 | 显示旧数据 | 事件驱动 + 开机/启动补刷 + 固定行不用 collection |
| 安全修复影响系统进程唤醒 | 漏码 | UID 白名单覆盖 system/phone/mms/telephony；真机冻结测试 |
| 范围膨胀 | 延期 | P0/P1/P2 分层；P1 不阻塞 4.0 |
| 升级丢数据 | 用户投诉 | 本地库新增、不删系统待办；升级测试；导出/回滚说明 |
| 历史版本号混乱 | 发布事故 | 版本映射 + 单一版本源 + tag 校验 |

## 七、已确认决策

1. 内部 3.2–3.9，公开 4.0.0；4.1–4.8 不作为公开版本。
2. 4.0 包含 UI、本地库、小组件、安全修复；不是只发 UI。
3. 首次启动让用户选简洁/进阶；数据共享。
4. 无 root Lite 放 5.0，不进 4.x。
5. UI 用 Compose + Room；Hook/引擎保持 Java。
6. 不重写 Git 历史；用映射文档和内部 tag 收口。

## 八、待确认问题

1. 模式最终命名：简洁/进阶，还是“轻享/专业”等。
2. 新用户默认写入目标：仅本地 / 本地 + 自动识别系统待办。
3. 是否在 4.0 提供“从现有小米笔记导入最近待办”；默认不做。
4. 历史保留期默认 90 天是否合适。
5. 取件提醒/闹钟/日历是否进 4.0；当前列为 P1，不阻塞。
6. 4.0 是否升级 targetSdk；Stage 0 spike 后决定。
7. ColorOS 是否有测试设备/社区 tester；没有则标记社区验证。
8. 官方 App 图标保留还是默认切自绘兜底（商标/分发合规）。

> 这些问题不阻塞 Stage 0；可以在对应阶段前给答案。
