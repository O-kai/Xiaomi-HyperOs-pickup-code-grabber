# 4.0 产品与 UI 规格（讨论稿）

> 工作名：**简洁模式 / 进阶模式**（可再改名）。
> 核心变化：App 不再只是“写进小米笔记的桥”，而是自己的**取件码收件箱**；桌面小组件是第二入口。

## 一、产品定位

**一句话**：给 root / LSPosed 用户的取件码收件箱——短信和通知自动抓，打开就能看、能复制、能标记已取件，桌面小组件直接显示待取件。

**目标用户**

- 已经在用 3.1.0 的老用户：不想重新学习，升级后仍能“一个页面解决”。
- 喜欢折腾的进阶用户：要自定义规则、通知来源、诊断、历史、主题。
- 新 root 用户：第一次安装，需要被引导完成 LSPosed / root / 通知 / 写入目标配置。

**JTBD**

1. 收到取件短信/通知时，不要漏。
2. 到驿站前，快速看到“还有几个件、码是多少”。
3. 取件时，一键复制码；取完一键标记。
4. 出问题时，知道是哪一层坏了，而不是“什么都没发生”。
5. 不想把短信内容上传到任何服务器。

**设计原则**

- **主任务优先**：打开 App 第一眼是待取件，不是体检和设置。
- **简洁默认，进阶可选**：普通用户不被规则/诊断打扰；需要的人能找到。
- **不静默失败**：识别、写入、同步失败都要有原因和下一步。
- **本地优先**：本地库是事实源；系统待办是可选出口。
- **一次只让用户做一件事**：引导、配置、测试都分步。
- **不用 emoji 当功能图标**；用矢量图标和明确文案。

## 二、双模式

### 2.1 简洁模式

- 单页滚动，无底部 Tab。
- 顶部：标题 + 运行状态胶囊（正常 / 需配置）。
- 状态卡只在异常时出现；正常时不占大块空间。
- **待取件列表**是页面主体：码、来源、地点、时间、复制/已取件。
- 快捷动作：粘贴短信添加、一键链路测试、添加到桌面。
- 核心设置：写入目标、通知提取、本地记录保留；收在一个“设置”入口里。
- 高级规则、诊断、主题、历史详情：只给一个“切换到进阶模式”的入口，不在主界面展开。

```
┌──────────────────────────────┐
│ 取件码助手        [运行正常] │
│ 3 个待取 · 规则 v7           │
├──────────────────────────────┤
│ 16-4-9626           [复制]   │
│ 菜鸟驿站 · 今天 14:20  [已取]│
├──────────────────────────────┤
│ 8-2-4411            [复制]   │
│ 丰巢 · 昨天 18:02      [已取]│
├──────────────────────────────┤
│ + 粘贴短信添加                │
│ 一键链路测试                  │
│ 添加到桌面                    │
├──────────────────────────────┤
│ 设置 · 切换到进阶模式         │
└──────────────────────────────┘
```

### 2.2 进阶模式

四个 Tab：

1. **取件**：待取件 + 历史 + 统计 + 小组件状态 + 一键链路测试。
2. **通知提取**：总开关、内置 App 列表（可逐个开关）、自定义来源、作用域提示。
3. **高级规则**：官方规则版本、我的规则、黑名单、错题本、诊断入口。
4. **设置**：写入目标、写入格式、外观（浅色/深色/跟随系统 + 强调色）、模式切换、更新、隐私、关于。

> 页面命名沿用用户已认可的“通知提取 / 高级规则”，不重新制造概念。

### 2.3 首次启动

- 新安装第一次启动：先出现“选择使用方式”页，两张卡片：
  - **简洁模式**：一个页面，打开就能取件；适合不想折腾。
  - **进阶模式**：四个页面，规则、来源、历史、诊断都能调。
- 默认高亮简洁模式；选择后进入配置引导。
- 老用户升级：保留原设置；首次进入 4.0 时同样出现一次选择页，默认选中简洁模式，可跳过。
- 选择结果存本地；设置里可随时切换，**数据不丢、不需要重装**。
- 切换后只重建界面壳，不重启进程；当前页面回到“取件”。

## 三、关键流程

### 3.1 首次配置

1. 选择模式。
2. 检查 LSPosed 注入。
3. 检查 root。
4. 检查作用域（android / phone / mms / telephony provider）。
5. 通知权限。
6. sqlite3 / 写入目标（仅在使用系统待办时需要）。
7. 一键链路测试。
8. 完成，进入取件页。

- 每一步只显示“通过 / 待处理 / 无法自动核对”，不倾倒长错误。
- 失败时给一个可执行动作（打开 LSPosed、授权 root、重新检测）。
- 允许“稍后再说”，但首页保留一条轻量提示。

### 3.2 收到取件短信

1. Hook 捕获 → 提取 → 本地库写入（唯一事实源）。
2. 去重：同一事件只处理一次；同一码+地点在窗口内不重复建记录。
3. 写穿到系统待办（若开启）。
4. 发通知：显示码，点击复制并打开取件详情；“已取件”直接更新本地 + 系统待办。
5. 更新桌面小组件。

### 3.3 打开 App

- 直接显示本地缓存，不等待 root 体检。
- 体检在后台跑，完成后只更新状态胶囊；异常才展开。
- 待取件按时间倒序；超过 3 天显示“可能已过期”提示，但不自动删除。

### 3.4 标记已取件

- 本地记录立即变为已取件（乐观更新）。
- 后台同步系统待办；失败则显示“已在本机标记，系统待办同步失败”，可重试。
- 小组件立即移除该行。

### 3.5 添加桌面小组件

- 简洁模式显示“添加到桌面”卡片；优先 `requestPinAppWidget`，不支持则给长按桌面 → 小组件的图文说明。
- 小组件空状态：“暂无待取件，收到短信后会出现在这里”。

## 四、桌面小组件规格

| 项 | 规格 |
|---|---|
| 尺寸 | 4×2 为主，4×4 为扩展；固定 3 行，不做滚动列表 |
| 内容 | 标题“待取件 N”、3 条记录（码 + 地点/来源 + 时间）、底部“查看全部” |
| 行操作 | 点码复制；点“已取”标记完成；点行打开 App 详情 |
| 刷新 | `updatePeriodMillis=0`，由事件驱动 `updateAppWidget`；开机/App 启动补一次 |
| PendingIntent | 每条记录用唯一 `data` URI，避免 extras 被忽略导致互相覆盖；全部 `FLAG_IMMUTABLE` |
| 深浅色 | 独立 `values-night`；半透明深色底 + 白字，两种壁纸都可读 |
| 字体 | 取件码用 monospace；地点最多 1 行省略 |
| 隐私 | 设置项“小组件隐藏取件码，只显示件数”；默认显示 |
| 空状态 | 不显示空白卡片；显示“暂无待取件” |
| 兼容 | 不使用 Android 16 已弃用的 collection API；不依赖 Glance |

## 五、视觉与可访问性

- **主题**：浅色 / 深色 / 跟随系统；强调色 3 套以内，不做 4 套全量换肤。
- **排版**：标题 24–26sp；正文 14–16sp；辅助 12–13sp；取件码 20–24sp monospace。
- **圆角/间距**：卡片 16–18dp；页面左右 16–20dp；卡片间距 10–12dp。
- **底栏**：进阶模式使用 Scaffold/inset 布局，内容 padding 包含底栏与系统手势区；禁止再出现底栏压住正文。
- **触控**：所有可点区域 ≥ 48dp；复制/已取件有明确文字或图标 + contentDescription。
- **字体缩放**：1.3× 不截断关键按钮；长文本可换行。
- **对比度**：正文 ≥ 4.5:1；状态色不只靠颜色区分，配文字。
- **动效**：150–250ms；不做重度模糊/透明叠层；列表更新用轻量过渡。
- **无网络也能用**：所有主界面不依赖网络；更新检查失败不阻塞。

## 六、文案规则

- 状态说人话：
  - “运行正常 · 3 个待取”
  - “通知权限未开，取件提醒不会弹出”
  - “已识别到取件码，但系统待办写入失败：root 未授权”
- 错误必须给下一步：
  - “去 LSPosed 勾选 Android 系统”
  - “重新检测”
  - “仅保存到本机”
- 不用“可能”“大概”掩盖失败；不确定就写“无法自动核对”，并给排查入口。
- 界面不出现 emoji 功能图标；保留 ✓/✗ 等文本符号。

## 七、非目标（4.0 不做）

- 不做账号、云同步、统计 SDK、广告。
- 不做第三方 todo（滴答/Notion）接入；保留通用后端接口，后续再评估。
- 不做无 root 自动读取；Lite 放 5.0。
- 不做锁屏小组件/超级岛；先把手表盘大小的桌面组件做稳。
- 不做自动删除历史；只做手动清理 + 保留期设置。

## 八、验收标准

1. 首次安装能在 2 分钟内完成模式选择 + 配置引导（有 root/LSPosed 前提下）。
2. 简洁模式从打开 App 到复制取件码 ≤ 2 次点击。
3. 进阶模式功能不少于 3.1.0 + 4.8 的并集；原有入口不丢。
4. 两种模式共享同一份数据；切换后待取件数量一致。
5. 深色/浅色、字体 1.3×、手势导航下无遮挡/截断。
6. 小组件收到短信后 1 秒内更新；点已取件后立即消失。
7. 所有失败路径都有可见反馈，不出现“什么都没发生”。

## 九、待确认

- 模式最终命名：简洁/进阶，还是“轻享/专业”等。
- 新用户默认写入目标：仅本地 / 本地 + 自动识别系统待办。
- 是否在 4.0 提供“从现有小米笔记导入最近待办”；默认不做，只显示说明。
- 历史保留期默认 90 天是否合适。
- 是否在 4.0 加“取件提醒/闹钟/日历”；当前列为 P1，不阻塞核心闭环。
