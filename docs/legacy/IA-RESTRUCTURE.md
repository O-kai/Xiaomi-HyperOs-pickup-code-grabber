## 三、重新分配方案

### 首页 —— 只放「现在能不能用」和「核心配置」

设计原则：**首页回答一个问题——它现在能正常工作吗？如果不能，我该做什么？**

| 顺序 | 内容 | 说明 |
|---|---|---|
| 1 | **状态卡** | 未激活时显示引导流程；已激活显示「一切正常 · 已激活」 |
| 2 | **未激活引导区** | 仅未激活时显示：一键部署 sqlite3 / 排查向导 / 具体缺失项 |
| 3 | **一键链路测试** | 从「规则」页移来。这是用户验证「能不能用」的最直接手段 |
| 4 | **写入与适配** | 从「应用」页移来。写入目标 + 环境适配，用户最关心的配置 |
| 5 | **官方规则集** | 从「规则」页移来版本信息（只显示版本 + 词表规模，不带「检查更新」按钮） |

**移出首页**：
- 双统计卡（适配应用 / 识别来源）→ **删除**（你指出的无价值）
- 项目版本信息 → 设置
- 是否有新版本 → 设置
- 反馈入口（GitHub / QQ 群）→ 设置

---

## 四、待确认的问题

1. **首页「未激活」的引导流程具体包含哪些步骤？** 现在的体检清单有 6 项（注入 / root / 作用域 / 通知 / sqlite3 / 笔记库），未激活时是逐条显示还是给一个「一键修复」？
2. **「语言」这一项现在没有实际功能**（跟随系统），是保留占位还是删掉？
3. **「应用」页改名**：叫「通知来源」还是「来源应用」还是别的？
4. **关于模块的作者**：ColorOS 作者 Artifical0、UI 作者 Seven2023Six，要写具体名字还是 GitHub ID？要不要加链接？
5. **首页的官方规则集**：只显示版本号，还是要显示「13 组锚点词 / 24 特征词 / 29 负向词」这种细节？
