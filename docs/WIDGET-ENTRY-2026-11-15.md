# 小组件的「添加入口」与「负一屏」可行性（2026-11-15）

> 起因：用户看到飞书长按图标能直接「添加小部件」，问我们能不能做到；
> 另外问能不能把小组件放到负一屏。
> 本文只记录**结论 + 证据 + 我们落地的方案**，实现见 commit。

## 一、结论速览

| 想要的入口 | 能不能 | 说明 |
|---|---|---|
| 长按图标 →「添加小部件」 | **能，但要自己声明** | MIUI 自带的那条只对它服务端清单里的合作应用显示；App 自己用**静态快捷方式**在同一张菜单里放一条，效果等价 |
| 点一下直接把组件落到桌面 | **不一定** | `requestPinAppWidget` 在 HyperOS 上「返回 true 但什么都不做」；已加结果回调 + 超时兜底 |
| 放到负一屏 | **不能** | 负一屏只收「小米小部件」（maml 卡片），标准 Android AppWidget 连入口都不显示；且这是商业化资源位，不对外开放 |

## 二、为什么长按图标那条「添加小部件」我们默认没有

1. **它是桌面自己加的，不是 App 声明的**。Android 侧只有 `ShortcutManager`（应用快捷方式），
   「小部件」这一项是 Launcher 自己检查 `AppWidgetProvider` 后插进菜单的，属实现细节。
2. **HyperOS 的小部件列表是在线内容 + 白名单**。小米.eu 论坛里 Xiaomi 方面的人原话
   （2026-06 关于「怎么让组件出现在 HyperOS 原生小部件区」）：

   > The normal widget picker is online content. Our server decides what shows.
   > You can't find documentation because we don't publish third-party widgets.

   换言之：能进「小米小部件」区的（Spotify、飞书……）是官方合作，
   **标准 AppWidget 一律落在「安卓小部件」兜底分类里**，并且：
3. 有开发者扒过 Spotify 的 manifest，发现只有「把小部件从安卓小部件分类里隐藏」的字段，
   **没有**「把第三方小部件加进原生区」的字段。

所以想拿到飞书那个位置的入口，唯一可控的办法是**自己声明一条应用快捷方式**——
它和飞书菜单里的「扫一扫 / 我的二维码」是同一个机制，落在同一张长按菜单里。

## 三、负一屏为什么放不进去

三条独立证据：

1. **MIUI 13 起，负一屏的「+」里就没有「安卓小部件」入口**（小米社区实测帖）：
   > 从负一屏添加「安卓小部件」：**不支持** —— 从负一屏进入小部件界面，
   > 「支持小部件应用」里并不能显示出「安卓小部件」的图标。

   安卓小部件只能从**桌面**进入：双指捏合 → 添加小部件 → 搜索 / 列表底部「安卓小部件」。

2. **小米官方对负一屏的定位是「小部件 + maml 模板卡片」**，
   而负一屏的小部件位属于**商业化合作资源**（小米澎湃 OS 开发者平台
   《负一屏商业化合作引导》：按 CPM / CPC 合作，年框客户）。个人开发者拿不到。

3. HyperOS 官方小部件设计规范里那句「小部件中心支持用户直接拖拽小部件至桌面或负一屏」，
   指的是**小米小部件**（进原生区的那些），不是安卓小部件。

### 那怎么办（给用户的替代）

- **放桌面第 1 页**：左滑即到，体感最接近负一屏；我们的组件本来就不占地方（4×2 起）。
- **负一屏放 App 图标**：负一屏的「常用应用 / 快捷功能」可以放任意 App 图标，
  点一下进 App 就能看到待取件列表（首页第一张卡）。
- 真要负一屏卡片 → 只能走小米小部件合作，不现实。

## 四、本次落地的东西

1. `res/xml/shortcuts.xml` + `LauncherActivity` 的 `android.app.shortcuts` meta-data：
   长按图标 →「添加小部件」（短标签）/「把「取件码」小组件添加到桌面」（长标签）。
   - 指向**已导出**的 `LauncherActivity`（res/xml 里不能写 `${applicationId}`，包名写死），
     再由它转交内部的小组件页 —— 某些桌面用自己身份启动快捷方式，
     直接指向非导出 Activity 会被拒。
   - `onCreate` / `onNewIntent` 两条路都接（桌面可能复用已有任务）。
2. `WidgetPin.quickPin()`：`requestPinAppWidget` + **`successCallback`**（`WidgetPinReceiver`）。
   - 每 500ms 探一次、最多 4 秒；命中任一「在正常走」的信号就收手：
     ① 收到「已固定」回调 ② 桌面上本 App 组件数变多 ③ 本页失去焦点（系统界面接管）；
   - 只有「4 秒一直握着焦点、一个组件也没多」才判定被系统吞掉；
   - 判定被吞后：先试桌面的小部件列表页（组件名命中才用），再给文字步骤；
   - 引导里点「去打开『桌面快捷方式』」会置一个标记，从权限页回来 `onResume`
     自动再发一次请求，用户不用自己再点一遍。
3. 引导文案改准（旧的写「长按空白 → 小部件」，HyperOS 上根本看不到本 App）：
   - 第 1 步是**打开「桌面快捷方式」权限**（部分 ROM 关着时会静默丢弃添加请求，
     这是社区里公认的 `requestPinAppWidget` 失效原因之一）；
   - 第 2、3 步才是双指捏合 → 添加小部件 → 搜索「安卓小部件」。
4. 顺带在引导里写明「负一屏放不进安卓小部件」，省得用户反复试。

## 五、真机验收清单（等手机连上逐条打勾）

- [ ] 长按桌面图标：菜单里出现「添加小部件」，图标是四宫格
- [ ] 点它：直接进小组件设置页，并弹出「正在请求系统放到桌面…」
- [ ] HyperOS 若静默失败：2.5s 后出现「系统没有响应这次添加」的引导弹窗（不是空白）
- [ ] 设置 → 应用管理 → 取件码助手 → 权限管理 → 打开「桌面快捷方式」后再点一次，
      看请求是否变成真的能加（能加则说明就是这道开关卡的）
- [ ] 桌面小部件列表页能不能被直接打开（`openWidgetPicker` 的两个候选类名是否命中）
- [ ] 小组件页「添加到桌面」按钮走新逻辑；「重新添加小组件」仍是纯引导
- [ ] 负一屏「+」→ 确认没有「安卓小部件」（把结论拍下来存档）

## 六、2026-11-18 真机验证（K90 Pro Max / HyperOS，已连机）

逐条结果：

- [x] **长按图标 → 菜单里出现「添加小部件」**（带雾霾蓝四宫格图标）。
      同一张菜单里**没有**系统自带的那一条 —— 反证了「系统那条只给白名单应用」。
- [x] 点它 → 进小组件设置页 + Toast「正在请求系统放到桌面…」+ 系统确认框
      「将小部件添加到桌面？」，点「添加」即落到桌面。（用户自己先验证过一遍）
- [x] 静态快捷方式已注册：`dumpsys shortcut` 能看到 `id=add_widget`、两个标签、
      `intent=...ACTION_ADD_WIDGET cmp=.../.LauncherActivity`。
- [x] **「桌面快捷方式」就是那道闸**：关着时 `requestPinAppWidget` 返回 true 但
      桌面的 AddItemActivity 立刻自己结束；打开后同样的调用会正常弹确认框。
- [x] 权限页可直达：`am start -a miui.intent.action.APP_PERM_EDITOR
      --es extra_pkgname io.github.okaidev.pickupcode` →
      「取件码助手」权限列表 →「其他权限」→「设置相关」→「桌面快捷方式」。
      已接进引导弹窗的主按钮（打不开时退系统「应用信息」页）。
- [ ] 没测到：`openWidgetPicker` 的两个候选组件名（这台机器上都不解析），
      所以主按钮永远走「权限页」这一支。真机上没出现过误跳转。

补充结论：**不要试图让系统那条「添加小部件」出现**。它由桌面的在线清单决定，
第三方应用没有任何 manifest/资源能挤进去；自己声明快捷方式是唯一可控路径。
