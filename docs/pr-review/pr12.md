# PR #12 评论（可直接粘贴到 GitHub）

> 标题：ci: 修复 Build APK 自 v3.0.0 起每次失败（setup-android 找不到 legacy tools 包）
> 结论：**内容已在仓库里**（commit `7919d2b`），可以关闭。

---

感谢 @ByteJuno，这个诊断完全正确。

`android-actions/setup-android@v3` 默认装 `tools platform-tools`，
而 SDK 仓库早就移除了 legacy `tools` 包 → `sdkmanager` 以 exit 1 退出，
job 在 Gradle 之前就挂了。这个失败模式很隐蔽：**看 Actions 列表只会看到「失败」，
点进去才发现根本没跑到构建**。

## 核对结果

`release/4.0` 分支（以及它的祖先 `main`）里，`.github/workflows/build.yml`
已经是修好之后的样子：

```yaml
- name: 设置 Android SDK
  uses: android-actions/setup-android@v3
  with:
    packages: 'platform-tools'

- name: 安装编译所需 SDK 组件
  run: sdkmanager "platforms;android-34" "build-tools;34.0.0"
```

对应提交：`7919d2b ci: 修复 setup-android 安装 legacy 'tools' 包失败导致的构建中断`

与你的 PR 差异只有一处（不影响功能）：我们这边少了那段解释性注释，
改为在 `docs/RELEASE-PROCESS.md` 里记录。

## 后续

4.0 的 `app/build.gradle` 仍是 `compileSdk 34` / `targetSdk 34`，
所以你写的 `platforms;android-34` + `build-tools;34.0.0` 是准确的。
等 4.0 发布时会一起生效，CI 会在 `v*` 标签上产出 debug APK 用于体验。

这个 PR 我关闭了，但功劳记在 CHANGELOG 里。谢谢！
