# 🧩 用户自定义规则 · 完全参考手册

> 适用版本：**v3.0.0+**
> 入口：App 右上角 **⋮ → 🧩 用户自定义规则（高级）**
> 官方规则集（`rules.json`）已覆盖全国主流快递；本功能用于补上「你所在驿站/学校的特殊格式」。

---

## 〇、先看这一段：权限边界（不可配置，永久生效）

用户规则**只能回答一个问题**：

> 「这条短信里，取件码 / 来源 / 地点 是什么？」

**做不到、也永远不会被允许做的**：

- ❌ 自定义 SQL
- ❌ 自定义要写入的数据库或表
- ❌ 自定义写入语句、目标文件、目标 App
- ❌ 读取你手机里的其他任何数据

> 这条边界写死在代码里（`UserRules` 类头注释）。
> 即使你的规则写错，最坏后果也只是「这条短信解析错了」，
> **绝不会**变成任意代码执行或数据库损坏。

---

## 一、为什么要用这个功能？

官方规则集再怎么更新，也追不全全国几十万家自建驿站、学校自提柜、物业柜的文案差异。

**你的号码就是最好的抓手**：驿站、快递员、物业都有固定号码发短信，
同一个号码发来的短信，模板几乎固定 —— 这比写复杂正则可靠得多。

```
官方规则（覆盖主流）  +  你的号码专属规则（覆盖你遇到的）  =  你的专属体验
```

## 二、四层匹配模式：怎么用发送方字段

「② 发送方范围」是本功能最重要的字段。按你手里的号码形态选：

| 模式 | 什么时候用 | 填什么 | 例子 |
|:--|:--|:--|:--|
| **🌐 不限来源（全局规则）** | 官方规则没覆盖到的短信，用它兜底 | 留空 | 任何短信都尝试 |
| **📞 精确匹配** | 驿站/快递员**固定号码** | 完整号码 | `1069888877` |
| **📞 前缀匹配** | **虚拟号：前几位固定、后几位随机** | 开头 2–15 位数字 | `1069` |
| **📞 包含匹配** | 号码记不住，但里面带文字 | 文字片段 | `菜鸟驿站` |

### 🎯 关于「虚拟号后几位随机」

这是真实存在的场景（106/1069/10655 等虚拟号段），所以专门做了**前缀匹配**：

```
你填 PREFIX = 1069
  → 会命中 1069888877
  → 会命中 1069123456
  → 会命中 1069999999   （同服务商后几位随机也没关系）
  → 不会命中 1008612345 （开头就不是 1069）
```

### 🎯 关于「固定快递员个人号」

手机号打 11 位，建议用**精确匹配**：

```
EXACT = 13800138000
  → 只有这个号发来的短信才走这条规则
```

### ⚠️ 格式要求（保存时会校验并明确提示）

- 精确匹配 / 前缀匹配：必须填**纯数字**（4–15 位 / 2–15 位）
- 填了文字又想用数字匹配？保存时会提示你改用「包含匹配」

## 三、优先级：多条规则同时命中怎么办？

```
精确匹配(3)  >  前缀匹配(2)  >  包含匹配(1)  >  全局规则(0)
```

即：**越具体的规则越优先**。

- 你配了「1069 开头」的专属规则，它不会被一条宽泛的全局规则抢先匹配
- 同一具体度下，按你界面里的**排列顺序**，靠前的优先

## 四、七个字段：哪些必备、哪些可选

| # | 字段 | 必要性 | 说明 |
|:--|:--|:--:|:--|
| ① | 规则名称 | **★必备** | 给自己看的，如「我们小区菜鸟驿站」 |
| ② | 发送方范围 | 可选 | 留空 = 全局规则。**强烈推荐填**，精准度最高 |
| ③ | 取件码正则 | **★必备** | 核心。例：`取件码\s*([A-Za-z0-9-]+)` |
| ④ | 捕获组 | **★必备** | 第几个小括号是取件码。`1` = 第一个 `()`；`0` = 整个匹配 |
| ⑤ | 来源 | 可选 | 留空 = 自动识别（推荐）；固定文本或 `$1` 引用 |
| ⑥ | 地点 | 可选 | 留空 = 自动识别（推荐）；固定文本或 `$1` 引用 |
| ⑦ | 地点正则 | 锦上添花 | 地点格式特殊时才用，如 `至(.+?取件)` |

### 💡 为什么建议 ⑤⑥ 留空？

自动识别已经能处理绝大多数情况。
**你写的固定值会覆盖自动识别** —— 如果短信模板以后变了，你的固定值反而会变成错的。
只有在你发现「自动识别出来总是写错了」时，才手动指定。

## 五、三个安全机制（必读）

### 1️⃣ 强制自测：不通过不允许启用

每条规则必须**自带测试样本**（粘贴真实短信 + 填写期望取件码）。
保存时会真实跑一遍，不通过直接拒绝保存，并逐条告诉你：

```
第 1 条样本不匹配：期望「1234」，实际「5678」
```

### 2️⃣ 耗时熔断：50ms

单条样本执行超过 **50ms** 会被直接拒绝，并告知你：

> 第 1 条样本耗时 320ms，超过 50ms 熔断阈值——该正则可能引发灾难性回溯，
> 在真实短信上会卡住短信处理流程，已拒绝启用。请简化正则后重试。

**为什么这么严**？因为你的规则会跑在**系统短信处理线程**上。
一个写得不好的正则（如 `(a+)+b`）能让系统卡住数秒到数分钟。

### 3️⃣ 危险构造扫描

保存时自动扫描并拦截：

| 危险写法 | 后果 | 状态 |
|:--|:--|:--|
| `(a+)+b` `(a*)*` | 嵌套量词 → 指数级回溯 | **自动拦截** |
| `.*.*` | 相邻通配 → 同上 | **自动拦截** |
| `+` `*` 叠加 | 量词重复 | **自动拦截** |
| 超过 300 字符 | 冗余/恶意构造 | **自动拦截** |

## 六、完整实战例子

### 场景：我们学校自提柜（官方规则不认）

**短信原文**：
```
【Uniview 智慧校园自提柜】同学您好，您本次的物品编号 XZ-77612
已放置在 A 栋 3 楼取件口，烦请本人前往领取
```

**填写方式**：

| 字段 | 填什么 |
|:--|:--|
| ① 规则名称 | `学校自提柜` |
| ② 发送方范围 | **前缀匹配** `1069`（学校虚拟号） |
| ③ 取件码正则 | `物品编号\s*([A-Z]{1,3}-[0-9]{3,8})` |
| ④ 捕获组 | `1` |
| ⑤ 来源 | 留空（自动识别会从【】取「Uniview 智慧校园自提柜」） |
| ⑥ 地点 | 留空（会自动提取） |
| ⑦ 测试样本 | 粘贴上面的短信，期望填 `XZ-77612` |

**结果**：待办自动写成 `📦 取件码 XZ-77612｜Uniview 智慧校园自提柜｜A栋3楼取件口｜时间`

---

### 场景：多个驿站分号码

```
规则 1：前缀 1069 + 「物品编号」正则    →  学校
规则 2：精确 1069888877 + 「取件码」正则 →  家里小区驿站
规则 3：全局 + 「提取码」正则            →  兜底
```

三者可共存，互不干扰；命中时按「精确 > 前缀 > 全局」自动选。

## 八、常见问题

**Q：规则写好了但没生效？**
1. 顶部的「启用我的规则」开关是否打开？
2. 发送方范围是否匹配得上？（点「🧪 测试」看完整链路试跑结果）
3. 官方规则**优先**还是用户规则优先？→ 用户规则优先，官方规则只在用户规则未命中时才生效

**Q：能写多少条？**
最多 20 条。够用了——超过说明该走「上报给官方」而不是自己堆规则。

**Q：规则会传到云端吗？**
**不会。** 规则完全存在你手机本地（App 私有目录 + `/data/local/tmp` 供系统进程读取），
从写入到匹配全流程不经过任何服务器——本模块**没有任何**将短信或规则发送出去的功能。
想彻底断网可在设置页开启「允许联网」总开关。

**Q：会不会影响官方规则？**
不会覆盖。优先级：用户规则 → 官方热更规则 → 编译内置默认。
你停用所有用户规则，就完全回到官方行为。
