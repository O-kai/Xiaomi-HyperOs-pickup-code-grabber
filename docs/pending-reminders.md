# 待取件推送与背屏（4.3.0）

“取件记录 → 推送上岛”可多选正式待取记录。保存后，通知和超级岛只展示所选包裹；选择保存在本地，后来新增的包裹不自动加入。所选包裹完成或删除后会从通知移除，全部所选包裹取完则撤下通知，不会换成未选包裹。取消全部选择可以停止上岛；“自动推送全部”恢复默认行为。

背屏单独使用安静的常驻通知，内容来自全部正式待取记录，独立于上岛选择。新增、完成、恢复待取、删除和地址补齐都会更新；无待取件时撤下。应用启动、首次解锁、开机或覆盖升级后恢复。没有网络轮询或定时查询包裹接口。背屏卡片保留 17 Pro Max 左侧摄像头避让；4.3.3 起，亮屏和 AOD 均直接显示件数、取件码和地点，不再用“唤醒背屏查看取件码”遮挡内容。`disable_popup` 始终为 false，避免静默更新把卡片移到宿主隐藏分组；仅首次创建设置 `enableFloat`，普通更新保持静默。

HyperOS 4 的背屏宿主另有应用支持列表检查。现代模块增加 `com.xiaomi.subscreencenter` 作用域，仅在已核对的方法签名匹配时，让本模块包名通过宿主支持列表入口；其他应用执行原检查。这样不依赖手工登记到系统应用表后记录被清掉的行为，也不修改其他应用的背屏开关。该适配与设备系统版本相关，找不到已验证签名时记录诊断，不尝试猜测其他方法。

拼多多普通“我的快递”列表目前未提供明确驿站地址，不从截断的物流描述、手机号或收货地址猜测。已有“取快递”汇总分组的 `address`、柜机详情的 `result.address`，以及同一详情模型的 `cnInOutBound.address` 可作为取件地址。加载这些数据时，按已验证的取件码及待取状态投递；同一码的未知地址原地补齐，保持一条记录，并刷新列表、通知、背屏和小组件。仍然只记录有完整取件码的待取包裹。

### 4.3.2 背屏“查看全部”

真实点击确认按钮已发送 PendingIntent，但 HyperOS 将列表安排到背屏，记录
`aborted activity ... show on rear display`，启动结果为 102。仅给 PendingIntent 的创建选项指定主屏不能解决：宿主发送时的选项会覆盖它。

按钮改用独立、不可变的列表 PendingIntent，并设置 NEW_TASK/CLEAR_TOP。背屏宿主内增加
`RemoteViews.startPendingIntent` 的定向 Hook：仅本模块创建的 Activity PendingIntent
将发送选项的目标改为主屏；广播和其他应用继续原参数，原方法只执行一次。
宿主重启加载后，通过背屏真实 RemoteViews 按钮触发，日志记录主屏路由，启动结果为 0；
取件列表出现在 Display 0 的活动栈并处于 Resumed。正面锁屏仍需正常解锁。
61 项 Android/Robolectric 测试通过，含按钮实际 performClick、主屏选项及其他应用/广播不改动的回归检查。
