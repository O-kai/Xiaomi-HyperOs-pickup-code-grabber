4.2.0 是**取件这条链路整体打磨**的一版：规则集升到 v13，取件码认得更准；提醒不再被系统省电策略推迟；桌面小组件从「添加」到「外观」都顺了一遍；取件记录可以按地点聚拢，也能展开看到每条的原始短信或通知。

没有新增需要学习的操作入口——老用户升级后原来的用法都还在。

### 规则集 v13：单段码不再被拆错

真机样本：

```
【菜鸟驿站】取件码D-3704的韵达81913包裹到派出所南隔壁快递站，请19:00前取
```

v11 会提取出 `3704` 和 `81913` 两个码——**两个都不对**。真实的取件码是 `D-3704`（前面的字母和横杠都是码的一部分），`81913` 是韵达的运单尾号。

根因不在锚点层：TierA 其实已经捕获了整串 `D-3704`，但 `dashPattern` 当时要求「至少两段」，单段「字母-数字」被形状校验判为非法直接丢弃；结果集为空后引擎退化到弱兜底，把 `3704` 和后面的运单尾号一起捡了回来。

规则数据改了三处：

- `dashPattern` 增一条「字母-数字开头、尾段 0~3」的分支，`D-3704` / `C-2605` / `M-2` 这类单段码形通过校验；纯数字仍要求至少两段，裸数字不会因此变成合法码
- `excludeHeadWords` 补 18 个承运商名（韵达/中通/圆通/申通/顺丰/邮政/EMS/极兔…），品牌名后紧跟的**纯数字**按运单尾号排除
- `excludeTailPhrases` 补 7 个物流状态词（已发货/已发出/已寄出/已揽收/已签收/派送中/运输中）

同一波还补了数字字母混排码（`8A3K` / `A3K8`），语料从 144 条扩到 179 条。

### 地点识别改成词表驱动

以前「店领」「您的包裹已到店」「找店员」会被当成店名。现在把地点成色的判定从代码搬进规则：否决词、噪声前缀、尾部动词、泛称词、尾段噪声词五张表都写在 `rules.json` 里，以后调这些词**不用发版**，热更新就能生效。

淘宝那条通知也顺手修了：

```
【订单物流】您购买的宝贝已送达菜鸟驿站，包裹待签收【取件码-1-9-7026】，手机号已加密…
```

以前整条被否（取件码为空），来源误写成「订单物流」、地点为空。现在取件码是 `1-9-7026`，来源「淘宝通知」，地点「菜鸟驿站」。

同码合并也补上了：同一个包裹先来短信、后来通知，不再互相覆盖，而是「后到的非空值覆盖、空值保留原来的」。短信给了地点、通知只给了来源，两条信息会合成一条完整的。

### 提醒不再晚点

以前用的是 `setInexactRepeating`，系统按省电窗口批量推迟，选了 9:00 可能 9:1x 才响。现在改成 `setExactAndAllowWhileIdle`，闹钟窗口为 0，到点就响。没给精确闹钟权限时会降级并给「去开启」入口。

一条短信里有多个取件码时，通知也按取件码拆成多条——以前拼成一条，看着像漏了一个。第 2 条起走静默渠道，不连响。

提醒时间的选择器换成滚轮，点几下就能选好。

### 桌面小组件：添加不再绕路

以前长按图标选「添加小部件」，会先闪一下主界面、进小组件设置页、再被弹回桌面，一共三次跳转。现在这条快捷方式指向一个透明中转页，点完直接把添加请求发出去，有权限时用户只会看到桌面上的系统确认框。

这里踩了一个真机的坑：在 `onCreate` 里发请求会抛 `IllegalStateException: Calling application must have a foreground activity or a foreground service`——那一刻页面还没 resume，系统认为 App 不在前台，直接拒绝。表现就是「有权限也只弹引导」。现在固定等 `onResume` 之后下一帧再发。

「添加小组件」和预览下面的「添加到桌面」也合并成同一条路径：有权限就直接加，没权限才提示去开权限。透明页上不再弹任何对话框——那种窗口上的 Dialog 会变成点不动也不消失的僵尸窗口。

外观这一块：配色、透明度、字号、显示内容都能在设置页里改，且**改完就地更新**，不再整页 `recreate()` 导致预览闪一下、滚动位置回顶。预览背景按桌面真实的格子 + 标定换算裁切，「精确对齐」和「按格子估算」会在标题上标明。

### 取件记录：按地点聚拢 + 看原文

列表右上角新增排序切换：**时间倒序**和**地址聚拢**。地址聚拢按完整地点分组，组内按时间倒序，组间按「该组最新一条」倒序——新消息到，整个分组连同组内的旧件一起顶到栈顶。未识别地点的记录单独成组，也按自己的时间参与排序，不固定沉底。

「全部」页里已取件仍然统一沉底、固定时间倒序，不塞进未取件的地址分组；「待取」和「已取」页都可以自由切换两种排序。搜索只作用于当前页，与排序叠加使用。

每条记录多了一个「完整信息」按钮（在「复制」左边）：点开就地展开，显示这条记录收到的所有短信/通知原文，带来源类型和时间；底部「全文复制」只复制这些原文，解析好的取件码继续走原来的「复制」按钮。展开一次只开一条，切页签或改搜索词自动收起。

### 更新日志和 QQ 群

首页版本号那一行现在可以点开「更新日志」，随时回看当前版本要点；新安装或版本变化后第一次打开会自动弹一次，同版本不重复打扰。开发者 QQ 群放在弹窗第一行，右侧「复制」按钮一点就复制群号。

设置页的「开发者 QQ 群」也提到最上面，就在「打赏作者」下面，右侧由箭头换成了「复制」按钮。界面模式的「简洁 / 进阶」现在是一个两段开关，两处显示方式完全对称，点另一个就直接切换。

### 升级须知

- **建议重启一次**：`NotiHook` 跑在 `system_server`，LSPosed 只在进程启动时注入。不重启的话通知通道还是旧代码
- **规则集 v13 热更新即可**：规则数据不需要升级 App；但地点词表、淘宝通知来源、同码合并这几项依赖引擎改动，需要升到本版才生效。`minAppVersionCode` 保持 405，4.0.5 及以上都能拉到规则
- **桌面小组件**：从旧版升上来的组件若显示错乱，长按组件「移除」后重新添加一次即可；设置页里也写了这条说明
