## 零、文案优先级锁定（防止来回改）

4.2.0 起，**所有对外文案按同一个顺序写**，从用户价值高到低：

1. **桌面小组件** —— 4.2.0 的最大更新。讲「现在能用什么、有什么功能」，
   不要写「闪一下」「弹回桌面」「抛异常」这类开发过程描述。
2. **取件记录** —— 地点聚拢 / 时间倒序，以及「完整信息」看原文。
3. **规则集** —— 认得更准，单段码 / 运单尾号 / 混排码。
4. **提醒** —— 精确闹钟，到点就响；通知按码拆分。

**不列为更新要点**：更新日志本身、QQ 群入口。
（QQ 群按钮是更新弹窗里的常驻联系入口，之前已要求放在第一行，属于界面布局，不是更新内容。）

**四档文案的关系**：软件内弹窗 = 4 条要点（价值 + 功能，一屏不滚动）；
酷安 = 中等详略，同样 4 段；GitHub 主仓 Release = 完整版，同样 4 节 + 升级须知；
**LSPosed 镜像仓 Release = 简版**，三段短文 + 「详见 GitHub Release Notes」——
模块商店页要一眼看完，长文放进去反而难读。
**顺序和用词骨架必须一致，只做详略裁剪** —— 改一处就要同步另外几处。

**保护数据**：不要把真机短信原文、具体地址、具体取件码写进对外文案；
讲码形只说「字母加数字」这种通用描述，给一个示意即可，不用真实样本。

**零散细节放在正文最后**（「还有一些小地方」）：用户没主动提、但日常会碰到的改进，
一条条列出来别用「若干细节优化」一句带过 —— 这是让人觉得作者用心的部分。
放在升级须知之前，让操作提醒压轴。

发版前检查：三处第一条都是小组件、最后一条都是提醒，没有把开发细节写进用户文案；
正文末尾有零散细节清单。

### 模块介绍页（README.md）

`docs/mirror/README.md` 已按 4.2.0 更新，发的时候把整份贴过去。这一版改了三处：

- 识别规则 v11 → **v13**：单段字母-数字码不再被拆错，运单尾号不误认，混排码可识别
- 桌面小组件：配色 / 透明度 / 字号可调，实时预览与桌面一致，长按图标可一键添加
- 取件记录：可按地点聚拢 / 时间倒序，每条能展开看原始短信或通知并全文复制；提醒改精确闹钟

环境要求、作用域那几项**没变**，照旧保留：root + LSPosed，作用域勾系统框架 / 电话 / 短信 / 电话和短信存储。
「系统框架」在 LSPosed 2.x 里置顶、带「推荐应用」标记，旧版叫「Android 系统」，勾一个就行。

### 这一版的 Release 正文

**镜像仓用中等篇幅，不要贴主仓那份完整版，但也不能太简陋。**

主仓那 2000 多字带表格和技术推导的正文，模块商店页读起来费劲；
但砍成三行字又太空，读者在商店页什么也了解不到。

**口径：保留核心小节与关键结论，砍掉详细展开与推导过程，砍掉一半左右；
末尾必须带链接**（GitHub Release 完整日志 / README / CHANGELOG），
让在商店页看到简介的人能跳去看全文。

结构：

1. 开头一段：这版主要是什么
2. 桌面小组件 —— 待取件直接上桌面，能看什么、能调什么
3. 取件记录 —— 两种排序 + 完整信息看原文
4. 规则集 v13 —— 认得更准（说结果，不讲推导）
5. 提醒 —— 精确闹钟 + 通知按码拆分
6. ⚠️ 升级注意 —— 重启一次 + 确认 LSPosed 作用域
7. 📖 相关链接 —— **必须有**

本次实际用的镜像正文（965 字符，主仓 2044，砍掉约一半）存在
`artifacts/release-mirror-body-4.2.0.md`。

**两仓正文的分工（以后都按这个来）**：

| | 主仓 | 镜像仓 |
|---|---|---|
| 正文 | 完整版（`docs/release-notes-<版本>.md`，从 tag 取） | 中等篇幅（核心小节 + 关键结论 + 链接） |
| 长度 | 2000+ 字符 | 约主仓的一半 |
| 作用 | 完整版日志存档 | 模块商店页展示 + 引导跳到完整日志 |
| 必备 | — | 末尾必须有「📖 相关链接」段 |

发完 5~60 分钟模块商店页自动刷新。
