## 二、用户手动添加包名：三层防护

用户可以在「应用 → 添加自定义来源」里填任意 App 包名。原实现只做格式正则，
存在四类真实风险：

  1) 重复/脏输入：同一包名填两遍、全角逗号、带前后空白。
     原实现保存的是原始文本，PKG_WHITELIST 是 List，会累积重复项。
  2) 拼错但不报错：正则只校验「像不像包名」，com.taobao.taobaoo 也能通过，
     保存成功却永远匹配不到通知。用户看到「开关开了、也加了包名，就是不工作」
     → 以为软件坏了。
  3) 高危包名：加入短信/微信/支付宝后，这些 App 的通知正文
     （可能含验证码/转账/私聊）会进入提取流程，违反最小权限原则。
  4) 误清空：无二次确认地清掉用户配置。

新增 PkgInput.java 统一校验与清洗：
- 分隔符规范化（换行 / 中英文逗号 / 分号 / 顿号 / 空白）
- LinkedHashSet 去重，静默丢弃重复项
- 格式校验（至少两段、字母开头、单包名 ≤128 字符、一次 ≤32 个）
- 是否已安装（PackageManager.getPackageInfo，取不到时不阻塞用户）
- 高危包名识别（SENSITIVE 表：系统短信/微信/支付宝/系统/小米笔记/短信存储）
- toStorageString() 返回清洗后的结果，落库的不是原文

交互设计：有问题时不强制禁止，而是弹窗说明风险，让用户选
「仍然保存」或「返回修改」——因为可能有正当场景（比如抓某个小众 App）。
一切正常时直接保存，不打扰用户。

## 三、PKG_WHITELIST 改用 LinkedHashSet

原 List 在用户重复填同一包名时会累积重复项，白名单越滚越长
（虽不影响匹配结果，但 currentPkgs() 展示会重复）。

## 四、「只留内置」加二次确认

原实现直接清空并 Toast，误触就丢了配置。
现在弹确认框：「你添加的自定义来源会被清空，只剩内置的 7 个。
这个操作可以重新添加，不会影响其它设置。」

## 五、探针工具增强

probe.py 每次连接都会自动读取并打印真实机型（getprop ro.product.marketname
等），避免靠记忆臆断设备型号；新增 info 子命令输出完整设备信息。
