## 顺带修复的真实 bug

1) LSPosed 作用域检查误报（真机表现为「LSPosed 未安装」/「模块未启用」，
   而同一份体检里注入其实是正常的）：
   - su 探测未遵循本仓库自己的哨兵约定（Diagnostics.PROBE_MARK），
     stdout 为空时返回「最后一个 su 路径不存在」的假错误
   - 配置库路径与表名/列名写死为 LSPosed 原版，而分支（如 Vector）改了库结构
     → 必然读不到
   现改为结构自适应：先读 sqlite_master 拿真实表名与列名再拼查询；
   没有模块状态表时退化为「存在作用域记录即视为已启用」，并照做作用域比对
   （避免反过来误报「齐全」）；结构完全识别不出时不下结论，
   把完整结构写进诊断报告，一次即可适配。
   同一模块存在多行记录（多用户/历史残留）时「最后一行覆盖」导致误判未启用
   → 改为任一行 enabled=1 即视为启用。

2) 用户自定义规则页保存后整页被清空：
   renderList() 收到的是整页根布局而非列表容器，removeAllViews() 把
   标题/开关/说明一并清掉。

3) 诊断报告日志段恒为空：root 下 logcat 受 PATH / SELinux 限制取不到，
   却显示成「无日志 → Hook 从未触发」的假结论。
   现依次尝试三种写法，失败时给出真实原因与替代做法。

4) 写入文本去 emoji：默认待办模板「📦 取件码 {code}｜…」→「取件码 {code}｜…」，
   「标记已取件」追加进笔记的标记同步去掉 emoji（界面 emoji 共清理 100+ 处）。
