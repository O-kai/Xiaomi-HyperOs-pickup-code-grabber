fix(ui): 版本号改为动态读取；来源识别排除「取件码」括号

## 一、versionCode 在界面上被写死

首页「项目版本信息」和版本详情弹窗里都把 versionCode 硬编码成 (310)：

  appVersionLabel() + " (310) · 规则集 v" + ...

后果：发版时改了 build.gradle 的 versionCode，界面仍显示旧的构建号，
用户看诊断报告或截图反馈时会对不上，也容易误导排查。

修复：新增 appVersionCode()，从 PackageManager 读取（兼容 API 28+ 的
getLongVersionCode），与 build.gradle 永远一致。

## 二、「包裹待签收【取件码-7-7-6622】」的来源被识别成取件码本身

真机实测待办内容：

  取件码 7-7-6622｜取件码-7-7-6622｜—

来源字段里出现了取件码本身。原因在 TodoWriter.bracketBrand()：
它取正文里第一个【...】的内容当作品牌名，而这条短信的括号里装的正是
取件码，不是品牌。

修复：括号内容含数字即判定为正文而非品牌名（品牌名如菜鸟驿站 / 兔喜生活 /
驿小哥 都不含数字，这条判据足够安全）。

## 三、识别不出来源时回显发送方号码

resolveSource() 的兜底分支返回 sender，于是待办里会出现
「1069888877」这种对用户毫无意义的号码。

按「识别不到就不显示」的原则改为统一返回「—」。
与用户明确要求一致：「实际来源和实际地点是没有的……直接不显示」。
