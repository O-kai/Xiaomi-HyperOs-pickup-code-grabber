## 二、为什么不是「在 GitHub 上直接 merge」

1. 5 个 PR 的 base 都是 `main`（= 已发布的 3.1.0）。
2. 本地 `release/4.0` 比 `origin/main` **领先 62 个提交**，而且
   `origin/main` 是它的祖先 —— 也就是说 4.0 发布时是**快进（fast-forward）**，
   不需要 force push，历史是干净的。
3. 如果现在把这些 PR 合到 `main`，等 4.0 推上去时会产生大面积冲突，
   而且同一份逻辑会在 3.1.0 与 4.0 两套架构里各维护一份（本项目最忌讳的「组合债」）。

所以采用：**把 PR 的内容移植进 4.0 → 用评论说明「已落到 release/4.0 的哪个提交」→ 关闭 PR**。
等 4.0 发布后，PR 作者若还想继续贡献，可以基于 4.0 重新开。

## 四、HyperOS / ColorOS 双系统校验记录

| 改动 | HyperOS 影响 | ColorOS 影响 | 验证方式 |
|---|---|---|---|
| `ColorOsProviderWake` | 类不存在 → 直接跳过，**零行为变化** | 放行系统身份唤醒模块 Provider | 代码层判断 + 日志可证（`WAKE skip` / `WAKE OK`） |
| 通知参数校验放宽 | 只会更宽松，不会更严 | 修复新系统上整条通道失效 | 逻辑等价性检查（见下） |
| `NotiEventWindow` 节流 | 抑制嵌套重载的重复处理 | 同 | 单测 8 项 |
| `NotificationText` | 只取公开字段 + 长度上限 | 同 | 代码审查 |
| 配置 `chmod`/`chcon` | `chcon` 失败也不影响写入 | system_server 才读得到配置 | 命令带 `|| true`，失败静默 |
| `handleDetailed` 回执 | 真机 uid 1000 调 Provider 实测 | 同 | 三条事件（写入/去重/新码）返回 `status` 正确 |

### 通知参数校验为什么是安全的

旧代码：`if (args.length < 10) return;` —— 一旦新系统参数个数变了，**整条通道静默失效**。
新代码：`if (args == null || args.length == 0 || !(args[0] instanceof String)) return;`
后面紧跟 `findNotification(args)`，找不到 `Notification` 对象就返回。

所以：
- 对「真通知」：两种写法都会通过（新写法更宽松）；
- 对「不是通知的调用」：旧写法靠长度挡，新写法靠 `instanceof Notification` 挡，
  **不会误处理**。

## 五、还没做的验证（需要你或 ColorOS 真机）

1. **ColorOS 17 实机**：`ColorOsProviderWake` 与 `chcon` 只有在 ColorOS 上才真正生效，
   我这边没有 ColorOS 设备，只能保证「非 ColorOS 完全不参与」。
   预期日志：开机后 `WAKE OK: N provider gate(s) hooked`。
2. **通知通道**：`NotiHook` 跑在 system_server，**必须重启手机**才会加载新代码
   （LSPosed 在进程启动时注入）。重启后建议用「一键链路测试」之外的
   真实通知验证一次（菜鸟/京东/抖音任意一条）。
3. **KernelSU 场景**：PR #13 的动机是 KSU 禁止 UID < 2000 取 su，
   这条只有在 KSU + ColorOS 组合下才能复现。

## 六、已知风险

| 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|
| `chcon system_data_file` 在部分 ROM 上不存在该上下文 | 低 | 命令带 `2>/dev/null \|\| true`，失败只影响「系统进程能否读到配置」，不影响写入 | 失败静默，功能回落到编译内置规则 |
| 通知通道改动需重启才生效 | 中 | 用户装完看不到变化，容易以为没修 | 在回复里明确告知 |
| `NotiEventWindow` 30 秒窗口可能吞掉「同一 App 30 秒内两条不同取件码但文本相同」 | 极低 | 文本相同意味着码也相同，本就该去重 | 持久化去重仍在 `TodoWriter` |
| `chcon` 后 App 自己是否还能读写 | 无 | App 走 root（magisk 域），不受标签限制 | 真机已验证写入 `exit=0` |
